# Agent Rule Resolution SOP

## Goal

避免代理在回答、联网、写入和风险判断时漏看更高优先级规则，尤其避免把“仓库规则”误当成“全局规则”的全部。

这份 SOP 默认适用于：

- 新会话首次进入仓库
- 用户追问“为什么你这样回答 / 为什么不是中文 / 为什么没联网 / 为什么直接写入”
- 需要判断回复语言、联网流程、写操作闸门、共享记忆义务时

## Rule Order

每次进入新任务或新仓库，按下面顺序读取规则，前一层优先级高于后一层：

1. 当前运行时硬约束
   - 当前会话的 system / developer / tool 指令
2. 用户当前回合的明确要求
   - 语言
   - 输出形态
   - 是否联网
   - 是否允许写入
3. 用户级全局规则
   - `$HOME/.codex/AGENTS.md`
   - `$HOME/.config/opencode/AGENTS.md`
4. 仓库级规则
   - `<repo>/AGENTS.md`
   - 相关 `.agents/skills/*/AGENTS.md`
5. 任务级补充材料
   - `.opencode/memory/current.md`
   - `$HOME/.codex/memories/current.md`
   - `docs/*_SOP.md`
   - 与当前任务直接相关的 README / DEBUG / TROUBLESHOOTING 文档

如果同一层出现多个文件：

- 先读与当前运行时直接对应的那份全局文件
- 再读同层其他补充文件
- 若仍存在冲突，优先选择更严格、可验证、风险更低的约束，并在输出中说明

## Mandatory Checks

正式回答或动手前，至少确认以下五项：

1. 回复语言
2. 联网检索流程
3. 读写模式与风险闸门
4. 是否要求更新共享记忆
5. 是否存在当前任务专属 SOP

只要这五项里有任意一项没确认清楚，就不能假设“仓库 `AGENTS.md` 已经覆盖全部规则”。

## Reply Language

回复语言判定按下面顺序执行：

1. 先看用户本轮是否明确指定语言
2. 若用户未指定，读取用户级全局规则
3. 若全局规则规定默认语言，则按全局规则执行
4. 仓库文档中的产品 i18n 规则，只用于产品行为，不直接改写代理对话语言

当前已核实的默认结论：

- `$HOME/.codex/AGENTS.md`
- `$HOME/.config/opencode/AGENTS.md`

两者都明确要求：

- 面向用户的结论、说明、分析、步骤、提醒与总结，默认使用简体中文回复
- 代码、命令、路径、环境变量、配置键、API 字段名、工具名、模型名、品牌名、库名、类名、函数名可以保留英文原文
- 若工具输出、报错、文档标题为英文，先给中文结论，再按需要附英文原词

## Execution Flow

### Step 1: Read the rule stack

至少完成以下读取：

- 当前会话硬约束
- 当前用户要求
- 用户级全局 `AGENTS.md`
- 仓库 `AGENTS.md`

如果任务属于长任务、规则争议、发布、联网、权限、删除、批量修改，再继续读取：

- 共享记忆
- 对应 `docs/*_SOP.md`

### Step 2: Extract hard constraints

把硬约束压缩成一份最小清单：

- 最终回复语言是什么
- 能不能联网，联网先后顺序是什么
- 当前是 `ReadMode` 还是 `WriteMode`
- 是否触发 `P0` / `P1`
- 结束前要不要更新记忆和验收

### Step 3: Decide action mode

若存在以下任一情况，先留在只读分析：

- 规则层级还没读清
- 全局规则与仓库规则看起来冲突
- 用户要求与更高优先级规则冲突，且冲突点还没说明白
- 风险等级不清
- 写入会改变系统状态但批准条件未满足

### Step 4: Execute

执行时遵守已提取的硬约束，不临时切语言、不跳过联网交叉核验、不跳过高风险闸门。

### Step 5: Final check

发最终答复前，逐项自检：

1. 有没有漏读用户级全局 `AGENTS.md`
2. 最终答复语言是否正确
3. 若涉及“最新 / 今天 / 目前”，是否给了绝对日期
4. 若发生长期有效的新结论，是否写入共享记忆
5. 若这是可复用流程，是否沉淀到仓库 SOP

## Recheck Triggers

出现下面情况时，必须重新跑一遍本 SOP，而不是沿用旧假设：

- 用户质疑“你为什么这样回答”
- 用户追问“有没有全局规则”
- 会话运行时切换
- 从仓库任务切到联网检索
- 从只读分析切到写操作
- 出现新的 `AGENTS.md`、新的共享记忆文件或新的任务 SOP

## Common Pitfalls

### Pitfall 1: 只看仓库 `AGENTS.md`

后果：

- 会漏掉用户目录下的全局规则
- 会把仓库局部约束误当作全局默认

修正：

- 先查 `$HOME/.codex/AGENTS.md`
- 再查 `$HOME/.config/opencode/AGENTS.md`
- 最后再看仓库 `AGENTS.md`

### Pitfall 2: 把产品语言回退规则当作对话语言规则

后果：

- 看到 “Keep runtime fallback in English” 就误以为代理应该用英文回复

修正：

- 先判断该规则是否描述产品运行时行为
- 只有明确写“reply / respond / 回答 / 回复”的条款，才用于代理对话语言

### Pitfall 3: 规则已查到，但没写进可复用资产

后果：

- 同样的问题会在后续会话重复发生

修正：

- 长任务写入共享记忆
- 可复用流程写入 `docs/*_SOP.md`
- 仓库 `AGENTS.md` 至少保留入口链接

## SOP Card

- 执行 [A]：先读全局规则，再读仓库规则，再读任务记忆与任务 SOP
- 验收 [B]：能明确说出“哪份文件、哪一行附近”决定了语言、联网和风险闸门
- 熔断 [C]：一旦规则层级不清或冲突未解，降级为只读分析，不直接写入或下结论
- 措施 [D]：采用更高优先级或更严格规则，说明理由，并把可复用结论写入记忆与 SOP
